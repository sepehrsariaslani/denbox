# Denbox for Mac

Denbox is a native SwiftUI movie and series library for macOS. It keeps the catalog, My List, and personal title ratings in SQLite, uses the API route patterns found in the supplied Simba APK for search and title details, and presents film and series pages with metadata, seasons, episodes, and selectable playback sources.

The interface defaults to Persian, with English selectable in Settings and right-to-left layout for Persian. Navigation, catalog search, discovery, watch history, personal ratings, downloads, charts, settings, genres, IMDb roles, public-title import, offline actions, and the embedded player's controls and common errors have Persian translations; some detail messages and raw provider/player errors still fall back to English. Original movie, series, person, and provider names remain unchanged.

Denbox bundles the Peyda font family for its Persian and English interface.

The built-in player runs libmpv in its own resizable window and supports seeking, playback speed, video/audio/subtitle track selection, selectable macOS audio output devices, external audio and primary/secondary subtitle files, audio and subtitle delay, saved subtitle size/position/font settings, aspect ratio and crop, rotation, chapter navigation, A–B repeat, a local playlist with reorder/shuffle, hardware decoding and deinterlacing controls, picture adjustments, a ten-band audio equalizer, frame capture with or without subtitles, and IINA-style keyboard shortcuts. With a personal OpenSubtitles API key saved in Settings, the Subtitles menu can search by title and local-file hash, download an SRT subtitle, and load it into the current libmpv session. The API key stays in Keychain. Its floating mini-player keeps the same libmpv session alive, stays above other windows, and can restore the original player window. Network playback uses a 45-second mpv cache with automatic pause/rebuffering and up to 8 seconds of rebuffering before resuming. The renderer redraws the last available frame during AppKit refreshes, updates its OpenGL surface on window/screen changes, and reconnects libmpv when full-screen movement creates a new context. It resumes from saved progress and records viewing activity locally. When a series episode ends, the player offers the next playable episode without closing the player. The build bundles libmpv and its runtime libraries from the installed IINA app; playback itself runs inside Denbox.

## API and data

- TVmaze cast cards can show a portrait and character name when that profile data is available. Selecting a cast member opens the local IMDb People page, using the matched IMDb person ID when available and falling back to an exact name match. The imported IMDb dataset provides the local filmography.

- The Mac client uses the APK route shapes `first/{key}`, `search/{query}/{key}`, `movie/by/{id}/{key}`, and `season/by/serie/{id}/{key}`. It uses the current HTTPS origin advertised by the APK config endpoint (`ninwinios.info/api`), then falls back to the known HTTPS service host. Catalog feeds remain on their configured HTTPS endpoints. The current cache remains available in `~/Library/Application Support/Simba/library.sqlite` so upgrading the app name does not discard the existing catalog.
- Opened movie and series detail responses are stored in that same SQLite database. Reopening a title displays its saved details immediately, including when the Mac is offline; entries older than five minutes refresh in the background and update the page when fresh API data arrives.
- Denbox does not call Frappe routes. API keys stay in macOS Keychain under the existing Simba service identity; they are not stored in this repository or app bundle.
- The media API can return plain HTTP streams and redirect them across hosts. For this personal build, ATS allows arbitrary media and network loads so the player can follow those HTTP redirects. API routes in Denbox still use HTTPS. This broad setting lowers transport security for network connections made by the app.
- Movie and series feeds are paginated in batches of 30. Use **Load more titles** in the Movies or TV Shows sections to continue through the feed. Pages are cached in the existing SQLite library, so titles loaded earlier remain available after restarting Denbox.
- The shared search field matches loaded titles, subtitles, and alternate names. It shows an in-progress state while remote catalog search runs, and searches started from discovery pages show the resulting catalog matches. My Ratings search stays local.
- Selecting a title opens a full detail page in the main window, with navigation back to the catalog. Direct video links from movie details and individual episode details can be downloaded to `~/Downloads/Denbox`. Completed downloads are linked to their catalog title and episode in SQLite, so reopening a detail page shows an offline badge and a **Play Offline** action; missing files are not shown as available. When the source honors HTTP byte ranges, Denbox downloads up to eight parts concurrently, reports bytes as they arrive, and verifies the assembled size; sources that reject or ignore ranges fall back to a normal download. HLS (`.m3u8`) and DASH (`.mpd`) playlists are not converted by this downloader.
- Detail-page Play and Download actions refresh API links when the cached details have no usable source; **Download this season** refreshes the series page, queues each episode with a direct-file link, and reports episodes that lack a direct download. Clicking an episode title in **Continue Watching** opens its series details, selects that episode, and scrolls to its row. Resume refreshes remote links before playback and prefers an already saved offline episode.
- **Download / refresh IMDb data** in Settings fetches IMDb's official public datasets over HTTPS. Denbox imports title metadata, ratings, episode numbering, person names, principal cast credits, and director/writer credits into `~/Library/Application Support/Denbox/imdb-metadata.sqlite`. The IMDb People page searches the local name index and shows paginated movie and TV filmographies; selecting a credit searches the Simba catalog and opens its details. The compressed source files are temporary and deleted after import. IMDb Charts builds local top-rated and most-voted lists from ratings and votes. Its Top 250 style ranking uses IMDb's published weighted formula and 25,000-vote minimum, but IMDb does not publish which voters count as regular voters, so the local result can differ from its official chart. **Popular Today** loads TMDB's daily trending movies or TV series as in-app cards; it needs the optional TMDB Read Access Token saved in Settings. This is a TMDB popularity feed, not IMDb's proprietary MOVIEmeter. **Box Office** parses Box Office Mojo's worldwide lifetime-gross chart into in-app cards with rank and worldwide gross; selecting a card searches the Simba catalog instead of opening the chart website. The Persian **Release Calendar** combines Box Office Mojo's US theatrical release dates with TVmaze's known upcoming episode schedule. It uses the Persian calendar, includes season/episode numbers and each show's usual airing days where TVmaze provides them, and caches the TVmaze schedule in `~/Library/Caches/Denbox` for 24 hours. Release and episode coverage depends on the source data; TVmaze attribution is shown in the calendar. IMDb's official bulk files contain no photos, biographies, plot text, or franchise membership. Title posters are matched through the configured Simba catalog and cached in `~/Library/Application Support/Simba/library.sqlite`; IMDb Franchises shows curated franchise collections as local IMDb title cards; selecting a card searches the local Simba catalog. Series matching prioritizes exact titles and uses release year to rank duplicate or fuzzy matches. Episodes match by title first and fall back to season/episode numbering such as `S01E01`, then display IMDb rating and vote count where available. Similar titles are a local genre-overlap ranking, not IMDb's official recommendations. Descriptions still come from the configured media API. The IMDb dataset is for personal, non-commercial use; it is not bundled with releases. Attribution: “Information courtesy of IMDb (https://www.imdb.com). Used with permission.”

- Metadata priority is field-specific. IMDb supplies its title IDs, ratings and vote counts, genres, year, episode ratings, and ordered principal credits. TVmaze fills series art and fallback series facts, and supplies cast portraits, characters, and IMDb person IDs when available; it never replaces IMDb ratings or film credits. Wikidata fills missing facts and can contribute Persian text. Optional TMDB adds matched title details such as original titles, content ratings, backdrops, and trailers. For summaries, Persian text from Filimo, HexDL, the Simba catalog, or public references remains ahead of English text. If IMDb has no cast data, TVmaze cast profiles are used; Filimo/HexDL cast names are the last fallback.
- Denbox automatically checks public Filimo and HexDL JSON search endpoints for movie/series titles in the loaded catalog, one title at a time, and again when a detail page opens. REA verified both search routes and their returned synopsis/image fields. A strict normalized-title match plus type/year checks filters results, then saves the Persian synopsis, poster, title, year/country, genres, and available ratings in the existing `public_title_metadata` SQLite table; matching art and synopsis enrich catalog cards as soon as the API response arrives. IMDb ratings/genres/years remain primary when present, and TVmaze portrait/character data stays attached to IMDb actor cards. Opening a title automatically captures visible provider-page facts such as cast/crew, season/episode listings, and any visible episode summaries, then caches its page-parser version and retry time. The **Search public pages** action forces a fresh capture. If a public JSON endpoint is unavailable, Denbox falls back to the site's visible search page in non-persistent WebKit. No site login is used. These lookups do not read player, stream, or download URLs; playback and download sources remain the configured Simba routes. Successful Persian matches refresh after 30 days; unsuccessful searches cool down for 24 hours, and page-detail retries cool down for 24 hours after a failed capture. The lookup/schema version update rechecks records made by earlier searches while keeping those saved rows readable. The **Check Filimo and HexDL for loaded titles** Settings action can force a catalog refresh. A public page URL can still be entered manually when automatic matching misses.
- Public reference metadata from Wikidata, TVmaze, and optional TMDB refreshes automatically in the background for movie/series titles in the loaded catalog and when a detail page opens. Requests are limited to three titles at a time. The **Check public references for loaded titles** Settings action can also retry eligible titles. Wikidata uses a matched IMDb title ID when available, with a strict title/year/type search fallback, to fill description, release year, runtime, genres, country, director, cast, and artwork; TVmaze adds series cast, cast portraits, character names, poster, summary, and rating. When configured, TMDB can add original titles, taglines, content ratings, networks, writers, keywords, trailers, and backdrops. Saving or replacing its token forces a fresh TMDB lookup for loaded titles. Tokens stay in macOS Keychain. Metadata lookups send title search terms or matched IMDb IDs; viewing history and My List are not sent. Results are cached locally and link to their source on the detail page. The IMDb dataset remains the primary source for IMDb ratings, genres, episode ratings, and ordered credits. TVmaze requires visible attribution and publishes its API data under CC BY-SA. TMDB attribution is shown in Settings. Metadata coverage varies by title.
- Startup reads the saved catalog first, then checks the IMDb dataset and enriches titles in a low-priority background task. Reference/public metadata is fetched in SQLite batches of up to 500 IDs and decoded away from the main actor; large detail payloads are parsed off the UI thread. Catalog matching creates only its three exact-title indexes, while year and fuzzy-search indexes stay lazy. Home shelves and episode/history rows instantiate only as they become visible. Similar-series rows use a partial covering index and a genre-set cache; completed offline files are indexed by catalog/episode identity and normalized title instead of rescanning every download for each episode row.

- Viewing activity stays in the Denbox SQLite database on this Mac. **Continue Watching**, **Watch History**, and **Viewing Stats** use saved playback sessions; the built-in libmpv player saves position and watched time and can resume. Movie details and each series episode now have a watched/unwatched control; changing an episode's API ID does not lose its saved watched state, and unmarking resets resume to the beginning. **Export JSON** in Viewing Stats includes local viewing progress, sessions, personal title ratings, and title snapshots. For videos opened directly from this Mac, the export can also include their full file paths; save the JSON somewhere you trust. **Import JSON** previews the file and merges it into this Mac: newer local progress and ratings win, duplicate history sessions are skipped, and existing data is not deleted. Imports accept schema versions 1 and 2 and files up to 50 MB. Clearing viewing history leaves personal ratings intact. Episode progress can match by season/episode label if the media API changes its episode IDs. Genre filters and preferences use the local IMDb genres. **For You** combines local viewing history, chosen genres, and your personal star ratings to rank IMDb candidates; titles already watched or rated are omitted. Recommendations need the IMDb datasets to be imported, and a candidate only becomes playable when it matches a title in the configured media catalog. The large IMDb candidate list is indexed and loaded only when **For You** is opened; repeated requests use an in-memory cache. Genre counts are loaded when **Genres** is opened. Use **Movies** or **TV Shows** to filter the loaded local catalog.

- Completed downloads store their catalog and episode IDs in SQLite. Reopening the title shows an offline indicator and a **Play Offline** action; Denbox checks that the file still exists before offering it.
- Rate each movie or series from its detail page with one to five stars. These personal ratings are stored only in the local SQLite library, separate from IMDb ratings, and appear in **My Ratings**. Denbox saves a title snapshot with each rating so it stays in that list after a catalog refresh removes the title.

## Build

```sh
mkdir -p dist/Denbox.app/Contents/{MacOS,Resources,Frameworks}
mkdir -p dist/Denbox.app/Contents/Resources/fa.lproj
mkdir -p dist/Denbox.app/Contents/Resources/Fonts
cp Resources/Info.plist dist/Denbox.app/Contents/Info.plist
cp Resources/AppIcon.icns dist/Denbox.app/Contents/Resources/AppIcon.icns
cp Resources/Denbox-Icon.png dist/Denbox.app/Contents/Resources/Denbox-Icon.png
cp Resources/TMDB-Logo.png dist/Denbox.app/Contents/Resources/TMDB-Logo.png
cp Resources/Fonts/*.ttf dist/Denbox.app/Contents/Resources/Fonts/
cp Resources/fa.lproj/Localizable.strings dist/Denbox.app/Contents/Resources/fa.lproj/Localizable.strings
cp /Applications/IINA.app/Contents/Frameworks/*.dylib dist/Denbox.app/Contents/Frameworks/
swiftc -parse-as-library -swift-version 5 -O \
  -target arm64-apple-macosx13.0 \
  -I Sources/MPV -framework SwiftUI -framework AppKit -framework OpenGL -framework Network \
  -framework Security -framework UniformTypeIdentifiers -framework WebKit -lsqlite3 \
  -Xlinker -rpath -Xlinker @executable_path/../Frameworks \
  Sources/SimbaMac.swift Sources/DenboxLanguage.swift Sources/DiscoveryFeeds.swift Sources/MPVPlayback.swift Sources/IINAPlaybackMonitor.swift Sources/PublicTitleMetadata.swift Sources/PublicMetadataDiscovery.swift Sources/PublicTitlePageImportView.swift Sources/ReferenceMetadata.swift \
  Sources/SegmentedDownloader.swift Sources/IMDbMetadata.swift Sources/ViewingActivity.swift Sources/OnlineSubtitleSearchView.swift Sources/OpenSubtitles.swift \
  /Applications/IINA.app/Contents/Frameworks/libmpv.1.dylib \
  -o dist/Denbox.app/Contents/MacOS/Denbox
codesign --force --deep --sign - dist/Denbox.app
```

The build links and bundles libmpv and its runtime libraries from the installed IINA app, then runs that engine inside Denbox. IINA must be installed to build this personal bundle; playback does not launch the IINA app. The bundle identifier and existing Keychain/database locations intentionally retain the Simba identity so this rename keeps the current API credentials, catalog cache, and My List. This build targets Apple Silicon and macOS 13 or newer. It is ad-hoc signed and not notarized.

The current embedded video surface uses AppKit OpenGL APIs, which the macOS SDK marks deprecated; the app still builds, but the renderer should be revisited for long-term macOS support.

## Verification

`Tests/IMDbChartRankingTests.swift` verifies the 25,000-vote boundary for movie and series Top 250-style lists, separate report-wide means, weighted ordering, miniseries inclusion, and deterministic vote-count tie-breaking using a local SQLite fixture.

`Tests/WatchRecommendationHistoryTests.swift` verifies that watched IMDb titles stay out of **For You** even when their progress records are older than the 2,000 most recent rows, while unfinished titles remain eligible.

`Tests/DenboxSourceParserTests.swift` checks movie and series source parsing, including the API's `downloadas` flag. `Tests/CatalogPersistencePerformanceTests.swift` measures durable writes for 1,000 titles and IMDb rows plus batched reads of reference/public metadata caches. `Tests/DownloadLookupPerformanceTests.swift` measures indexed offline lookups across hundreds of downloads and checks title fallback and missing-file handling. `Tests/OfflineDownloadPersistenceTests.swift` checks that completed media remains discoverable after reopening SQLite, tolerates regenerated episode IDs, and ignores missing files. `Tests/WatchStatusPersistenceTests.swift` checks manual mark/unmark, regenerated episode IDs, resume reset, and completion statistics. `Tests/PersonalRatingPersistenceTests.swift` checks creating, updating, reloading, validating, and clearing local personal ratings. `Tests/StartupResponsivenessTests.swift` measures startup with 2,000 saved titles and checks that recommendation indexing stays lazy. `Tests/IMDbGenreIndexPerformanceTests.swift` checks that catalog matching builds only exact-title indexes, plus genre-index migration, recommendation ordering/ranking, and in-memory caches; with `--database PATH` it measures an installed IMDb database. `Tests/IMDbEnrichmentPerformanceTests.swift --parser-only` checks that large synthetic episode details parse away from the main actor. `Tests/APIRoutePerformanceTests.swift` measures how quickly the first playable route wins over a slow alternative and verifies the useful-details fallback. `Tests/PlaybackRoutingTests.swift` checks that Denbox initializes embedded libmpv, updates core playback controls, and does not launch IINA. `Tests/OpenSubtitlesTests.swift` checks the movie hash, release-name normalization, and API-result decoding. `Tests/PublicTitleMetadataTests.swift` checks Filimo/HexDL URL allowlists, strict title matching, Persian synopsis priority, structured public facts and genre mapping, old SQLite JSON compatibility, schema-version rechecks, retry cooldown, forced refresh, and local JSON persistence. `Tests/ReferenceMetadataTests.swift` checks TMDB, TVmaze, and Wikidata parsing, strict title/year matching, token-gated refresh behavior, merge behavior, both SQLite metadata caches across reopen, lookup cooldown persistence, and attribution. `Tests/IINAPlaybackMonitorTests.swift` checks the separate Unix-socket monitor implementation; the current embedded player reports progress directly and does not use that monitor. `Tests/SegmentedDownloaderTests.swift` uses a local synthetic HTTP server to verify concurrent range assembly/checksum and the no-range fallback. `Tests/DenboxLiveAPITests.swift --catalog-only` verifies the live movie/series feeds and details; `--mpv-probe-only` opens live movie and episode links with their API headers through libmpv; the full run also checks arbitrary HTTP byte ranges and pagination. Tests print counts and sanitized error codes only, never API keys or media URLs.

## System Picture in Picture

Denbox dynamically loads macOS's private `PIP.framework` and moves the active `MPVRenderView` into the system PiP controller, then restores that same view to the player window when PiP closes. The floating mini-player remains a separate option. This follows the lifecycle recovered from IINA with REA and is intended for this personal build; the private framework can change between macOS releases and is not suitable for Mac App Store distribution.
